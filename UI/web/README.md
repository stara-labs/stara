# Stara Web

This package implements a synthetic, session-only coordination workspace. Home,
Work, Conversations, App activity, Knowledge inspection, and collaborator context
are navigable. Source choices and draft text do not grant authority, contact a
participant, change a source record, or verify an external outcome.

## Commands

Run from the monorepo after its dependencies and generated token output are present:

```sh
pnpm --filter @stara/web dev
pnpm --filter @stara/web typecheck
pnpm --filter @stara/web test:unit
pnpm --filter @stara/web test:integration
pnpm --filter @stara/web test:coverage
pnpm --filter @stara/web build
pnpm exec playwright test --config tests/e2e/playwright.config.ts
```

The development server uses port 5173. Both development and preview proxy `/api`
to `API_PROXY_TARGET`, defaulting to `http://127.0.0.1:3000`. Production build
output is `UI/web/dist/index.html` with hashed assets. The Playwright default
starts the compiled API on 4174 and the built preview on 4173, with server reuse
disabled. The API and web must both be built first. For a running Compose
candidate, set `STARA_EXTERNAL_SERVERS=1` and
`STARA_E2E_BASE_URL=http://127.0.0.1:5173`.

The browser entry waits for `GET /api/runtime-config` before mounting the
workspace. Run the API alongside the web development server; an unavailable API
shows a generic failure instead of a workspace with an unknown environment.
The response must contain exactly `schemaVersion: 1` and an `environment` of
`development` or `staging`. Missing, malformed, or additional fields are rejected.
Configuration is fetched with `cache: 'no-store'`; no build-time environment
values or browser storage select the application environment.

Set `STARA_ENVIRONMENT=staging` on the API to display the persistent,
non-dismissible staging notice. The API defaults to `development` when that
variable is absent, so local development has no staging notice. `RuntimeApp`
owns loading and failure states; direct `App` composition defaults to development.
Exactly one notice is mounted: above the frame during ordinary use and inspection,
or inside an active native dialog so its text remains accessible while the
background is inert. It has no live-region announcements or dismiss control.

Each Playwright invocation reserves a new UUID-based directory under
`tests/e2e/.artifacts/<runId>/`, containing `results/`, `report/`, and `run.json`.
Metadata records arguments (including filters), server mode, base URL, timestamps,
configured projects, test count, lifecycle, and final status. A forcibly terminated
run may remain `configured` or `running`; that is not a passing result. Retries
remain zero. Use the configured reporters and output directory; CLI overrides
can disable lifecycle reporting or redirect evidence.

An optional `STARA_E2E_RUN_ID` must start with `run-`, followed by 1-80 lowercase
letters, digits, underscores, or hyphens. The directory must not already exist.
Traversal, absolute paths, and reuse fail before test-output cleanup. Leave the
override unset for automatic unique IDs across functional/accessibility reruns.
CI should retain `tests/e2e/.artifacts/**`, including all failed and successful
runs, not just the newest `report/` or `results/` directory.

## State and Boundaries

`workspace.ts` owns the working set and per-context session state independently
of dimensions. `fixtures.ts` contains only synthetic domain records. Context
panels remain mounted while inactive so scroll and selection are preserved;
closing removes workspace presence, retaining state for a later reopen in the
same session. Nothing is written to browser storage. A new conversation starts
with an empty, unsent draft.

Tab keys use arrows, Home, and End for navigation; Alt plus left/right arrow
reorders; Delete closes a working tab. The context switcher exposes explicit
reorder controls and the full ordered set, including closed contexts. The Home
tab cannot close or reorder. Pointer dragging uses the same reducer as keyboard
reordering. Inspection and source comparison remain separate from opening a
canonical working context.

`@stara/ui` exports shared primitive source. All icons pass through its `Icon`
component. Generated CSS is imported through `@stara/ui/styles`; it is supplied
by the integrator, never regenerated by the ordinary web build. Local configs
are self-contained and require no pending shared TypeScript config.

## Verification Contract

`UI-SHELL-01` covers identity, ordering, close/reopen, and resumable state.
`UI-SHELL-02/03` cover composed selection, inspection, drafts, navigation,
creation, local views, and responsive focus. `UI-PANEL-01` and `UI-TABS-01` cover
geometry bounds and pointer interaction contracts. `UI-ENTRY-01` includes the
application entry point in the eligible source set. `UI-FIXTURES-01` guards
role-only people, neutral synthetic addresses, unverified outcomes, and visible
simulation and authority boundaries in each seeded composition. Browser journeys exercise
the built artifact, same-origin health, real scroll, overflow, and canonical
reopening. Accessibility checks cover Home, Conversation, and App activity
compositions in both themes at 1440, 1100, 900, 700, and 390px, with text zoom,
reduced motion, forced colors, keyboard operation, and automated axe scans.

Coverage includes every authored `src/**/*.{ts,tsx}`, including unexecuted
files. Only type declarations are excluded; CSS is outside V8's executable
denominator. The package gate requires 90% lines and 85% branches. Reports belong
at `.artifacts/coverage/web` in the integrated repository. Browser reports are
nested beneath `tests/e2e/.artifacts/<runId>/{results,report}`, with lifecycle
metadata in the sibling `run.json`. `UI-EVIDENCE-01/02` cover collision rejection,
retention, path validation, and consistent invocation identity in workers.
Automated evidence does not establish
manual screen-reader acceptance, Product acceptance, or release authorization.
